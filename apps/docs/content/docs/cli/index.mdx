---
title: CLI
description: Authenticate, manage repositories, issues and pull requests, and call the REST API with pst or pushstack.
---

The `@pushstack/cli` workspace provides the `pst` and `pushstack` commands over
the [REST API](/docs/api). It requires Node.js 22 or newer and is published to
npm as `@pushstack/cli`:

```sh
npm install -g @pushstack/cli
pst --help
```

Until the first npm release lands (see
[releasing.md](/docs/internals/releasing)), build and run it from a checkout of
the monorepo:

```sh
pnpm install
pnpm --filter @pushstack/cli build
node apps/cli/dist/bin.js --help
node apps/cli/dist/bin.js auth login --with-token < token.txt
node apps/cli/dist/bin.js auth status
node apps/cli/dist/bin.js repo list
node apps/cli/dist/bin.js repo view alice/project --json nameWithOwner,url
node apps/cli/dist/bin.js repo create project --private --add-readme
node apps/cli/dist/bin.js api repos/alice/project
```

Create a personal access token on your PushStack host. Login verifies the token
and saves it in an owner-only `hosts.json` file. The token is stored as plain
text. `auth status` masks it, `auth token` prints it, and `auth logout` removes
the saved credential.

The default host is `git.nandan.fyi`. Set `PST_HOST` or pass `--hostname` to
select another host, including `localhost:3000` for local development.
`PST_TOKEN` overrides saved credentials. `PST_REPO` supplies an `OWNER/REPO`
when a command would otherwise infer it from git remotes. `PST_CONFIG_DIR`
selects the configuration directory; the default is
`$XDG_CONFIG_HOME/pushstack` or `~/.config/pushstack`.

`repo create` requires `--public` or `--private` and creates repositories under
the authenticated account. It supports `--description`, `--add-readme`,
`--gitignore`, and `--license`. `repo list` accepts an owner, `--limit`,
`--visibility public|private`, and `--json` fields.

`issue list` (`ls`) shows 30 open issues by default. Use `--limit/-L`
(1–10000), `--state/-s open|closed|all`, repeatable `--label/-l`, and
`--assignee/-a` to filter. Labels may be comma-separated and are combined as
an AND filter. The assignee filter accepts a login, `@me`, `none`, or `*`.
Pagination follows API Link headers and counts only issues, excluding pull
requests from the shared issues API.

`issue view <number>` displays an issue. Both list and view accept `--json`
with comma-separated fields: `number`, `title`, `body`, `state`, `stateReason`,
`url`, `author`, `assignees`, `labels`, `createdAt`, `updatedAt`, `closedAt`.
State and reason values use uppercase GitHub CLI naming. Authors and assignees
include `login`; labels include `name`, `color`, and `description`.

`issue create` requires `--title/-t`; supply `--body/-b` or
`--body-file/-F path` (`-` reads stdin). Labels and assignees support repeated
flags or comma-separated names; `@me` resolves to the active token's account.
`issue close <number>` accepts `--reason/-r completed|not_planned` (default
`completed`), and `issue reopen <number>` reopens it. These commands print the
issue URL. View, close and reopen reject pull request numbers.

All issue commands accept `--repo/-R OWNER/REPO` and `--hostname`, using
`PST_REPO` and then matching git remotes when `--repo` is omitted. Each
subcommand supports `--help`. Creation is noninteractive; no editor or
comment-on-close option is provided.

```sh
pst issue list -R alice/project -l bug -a @me --json number,title,url
pst issue create -R alice/project -t "Fix login" -F description.md -l bug
pst issue view 12 -R alice/project
pst issue close 12 -R alice/project -r not_planned
pst issue reopen 12 -R alice/project
```

`pr list` (`ls`) shows 30 open pull requests by default, as number, title,
head branch, state and creation time. It accepts `--limit/-L`,
`--state/-s open|closed|merged|all` (closed includes merged, like gh),
`--head/-H` and `--base/-B`. `pr view` and the other commands below take a
number (`7`, `#7` or a pull request URL), a head branch name, or nothing for
the current branch's open pull request. List and view accept `--json` with
`number`, `title`, `body`, `state` (`OPEN`/`CLOSED`/`MERGED`), `url`,
`author`, `headRefName`, `headRefOid`, `baseRefName`, `baseRefOid`, `isDraft`,
`createdAt`, `updatedAt`, `closedAt`, `mergedAt`.

`pr create` requires `--title/-t` and takes `--body/-b` or `--body-file/-F`;
`--head/-H` defaults to the current branch and `--base/-B` to the repository's
default branch. It prints the pull request URL. `pr merge` creates a merge
commit (`--merge/-m`, the default; `--squash`/`--rebase` are rejected by the
server) with optional `--subject/-t`, `--body/-b`/`--body-file/-F` and
`--match-head-commit SHA`; `--delete-branch/-d` then deletes the head branch on
the server. `pr close` and `pr reopen` accept
`--comment/-c TEXT`; merged pull requests can't be closed or reopened.
`pr checkout` (`co`) fetches the head branch into a local branch of the same
name (`--branch/-b NAME` to rename), fast-forwarding an existing one or
resetting it with `--force/-f`. `pr merge --delete-branch` is not yet available.

```sh
pst pr create -t "Fix login" -F description.md
pst pr list -s merged --json number,title,mergedAt
pst pr merge 7 -t "Fix login (#7)"
pst pr close 8 -c "Superseded by #7"
pst pr checkout 7
```

`api` supports `--method`, `--header`, raw `-f key=value` fields, typed
`-F key=value` fields, `--input`, `--include`, and `--paginate`. Requests use
the selected host's `/api/v3` API; pagination keeps credentials on that host.

The CLI covers authentication, repositories, issues, pull requests and direct
API requests. Interactive login, cloning and pushing are not implemented.
